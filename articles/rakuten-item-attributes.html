楽天CSVの「必須の商品属性を指定してください」エラーの直し方｜ブランド名・代表カラーがマスター値で弾かれるとき

楽天市場（RMS）にnormal-item.csvをアップロードしたら、「必須の商品属性（ブランド名／メーカー型番／代表カラー）を指定してください」というエラーで弾かれた——。

先に結論です。商品属性は 項目 / 値 / 単位 の3点セットのカラムで設定します。そしてヘッダー名は 商品属性（項目）1 のようにカッコが先、番号が後です。商品属性1（項目） と書くと「項目名が正しくありません」で弾かれます。

さらにもう1つ、値を入れたのに弾かれる場合の原因があります。ブランド名と代表カラーは楽天のマスター値と照合されるため、独自の色名やブランド表記は受け付けられません。

この記事では、商品属性カラムの書き方、マスター値照合の対処法、そしてジャンルごとに必須属性が違う点の確認方法を解説します。

結論：商品属性は「項目・値・単位」の3点セット

商品属性は、次の3つのカラムを番号で対応させて設定します。

カラム名 役割 例
商品属性（項目）N 属性の名前 ブランド名
商品属性（値）N 属性の中身 ヤマハ
商品属性（単位）N 値の単位 cm、kg など（不要なら空）

N は1〜100まで使えます。同じ番号の「項目」「値」「単位」が1組の属性になる構造です。単位が不要な属性（ブランド名など）では単位カラムは空で構いません。なお商品属性はSKUレベルのカラムなので、マルチSKU商品ではSKU行ごとに値を入れる必要があります。

ヘッダー名は「カッコが先・番号が後」

最も多い誤りがヘッダー名の書き方です。

  • 誤：商品属性1（項目）
  • 正：商品属性（項目）1

商品属性（値）1、商品属性（単位）1 も同じ形式です。楽天はヘッダー名の完全一致で列を識別するため、この位置が違うだけでその列が認識されず、「項目名が正しくありません」というエラーになります。

なお、一部の項目だけでなく全項目にエラーが出ている場合は、ヘッダー名ではなく文字コードが原因です。normal-item.csvは Shift-JIS（cp932）で保存してください。

記入例：ブランド名・メーカー型番・代表カラー

電子ピアノを例にすると、次のようになります。

商品属性（項目）1 = ブランド名      商品属性（値）1 = ヤマハ
商品属性（項目）2 = メーカー型番    商品属性（値）2 = YDP-166B
商品属性（項目）3 = 代表カラー      商品属性（値）3 = ブラック

CSVの1行として見ると、商品属性（項目）1 列に「ブランド名」、商品属性（値）1 列に「ヤマハ」……と横に並びます。3つの属性を設定するなら、商品属性（項目）1〜3 と 商品属性（値）1〜3 の計6列を使うことになります。

マルチSKU商品でカラー違いを扱っている場合、代表カラー の値はSKU行ごとに変わります。ブラックのSKU行には「ブラック」、ホワイトのSKU行には「ホワイト」を入れてください。全行に同じ値をコピーしてしまうミスが起きやすいポイントです。

値を入れたのに弾かれる：マスター値との照合

「項目も値も入れたのに通らない」という場合、原因は値そのものが楽天のマスター値と一致していないことです。

ブランド名と代表カラーは、楽天が持つマスター値と照合されます。 商品を製品カタログに正しく紐づけるための仕組みなので、店舗が自由に文字列を決められるわけではありません。

独自の色名は標準色名に寄せる

つまずきやすいのが代表カラーです。商品名やパッケージに書かれた色名をそのまま入れても、マスター値になければ弾かれます。

  • 「マットブラック」「ピアノブラック」「墨黒」→ ブラック
  • 「オフホワイト」「アイボリーホワイト」→ ホワイト
  • 「ダークブラウン」「ウォルナット」→ ブラウン

代表カラーには ブラック／ホワイト／ブラウン／ベージュ といった標準的な色名を使うのが基本です。商品名や説明文では「マットブラック」という訴求力のある表記を使い、代表カラー属性だけは標準色名にする、という使い分けで問題ありません。属性値は検索・絞り込みのための分類であって、キャッチコピーではないと考えると整理しやすいです。

ブランド名も同様で、「YAMAHA」「ヤマハ株式会社」など表記ゆれのある書き方より、マスターに登録されている表記に合わせる必要があります。

エラー文の指定に従うのが一番早い

マスター値の一覧を自力で探すより確実なのは、エラーメッセージが指定している表記にそのまま合わせることです。楽天のエラーは、どの属性が問題か、どういった値が想定されているかを示してくれることが多く、その指定どおりに直すのが最短ルートになります。推測で何度も書き換えてアップロードし直すより、結果的に早く終わります。

必須属性はジャンルごとに違う：RMSで確認する

ここが重要な前提です。どの商品属性が必須になるかは、ジャンル（全商品ディレクトリ）によって決まります。

  • あるジャンルでは ブランド名 と メーカー型番 が必須
  • 別のジャンルでは 代表カラー も必須
  • ジャンルによっては商品属性が必須でないこともある

したがって、「ブランド名・メーカー型番・代表カラーを入れておけば万能」という汎用テンプレートは作れません。登録しようとしているジャンルで何が必須なのかをRMSで確認するのが正攻法です。このジャンル依存性は、次の2つの状況で特に効いてきます。

ジャンルIDを差し替えたとき

ジャンルIDが古くて弾かれ、新しいIDに差し替えた——という場面では、必須属性の要件も一緒に変わっている可能性があります。ジャンルIDを直したら別のエラーが噴き出す、という展開はこれが原因です。

過去のCSVを流用したとき

前回登録が通ったCSVをコピーして別ジャンルの商品を作ると、属性が足りずに弾かれます。「前回通ったから大丈夫」は通用しません。流用時はジャンルIDと必須属性の両方を確認してください。

なお、カタログID（JANコード）が必須かどうかもジャンルによって決まります。商品属性のエラーとカタログIDのエラーはセットで出やすいので、あわせて確認しておくと手戻りが減ります。

商品属性の入力漏れを自動チェックできる無料ツール

SKU数が増えると、「どのSKU行で属性値が空になっているか」「ヘッダー名の番号の位置が正しいか」を目視で確認するのは現実的ではなくなります。

無料のブラウザツール RakuCSV Studio の点検機能を使うと、手元のnormal-item.csvを読み込ませるだけで、商品属性1（項目） のようなヘッダー名の誤記や、属性値が欠落しているSKU行を自動で検出できます。あわせて、文字コード（UTF-8保存）の問題、環境依存文字の混入、カタログIDの入力漏れ、画像パスの書式ミスといった別系統のエラー要因も同時に診断し、修正済みのCSVをダウンロードできます。ブラウザ上で動くのでインストールは不要です。

ただし、マスター値との照合は楽天側で行われるため、値が正しいかどうかは最終的にRMSへのアップロードで確認することになります。ツールで形式面のエラーを潰しておけば、マスター値の調整に集中できます。

さらに詳しく：CSV登録を「一発で通す」ために

商品属性を直しても、その先には「ジャンルIDが存在しない・古い」「カタログIDもしくはカタログIDなしの理由が必須」「画像パスは相対パスでご指定ください」「スマートフォン用商品説明文に許可されないHTMLタグ」など、系統の異なるエラーが控えています。
