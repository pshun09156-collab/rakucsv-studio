楽天CSVの「カタログIDもしくはカタログIDなしの理由が必須です」エラーの対処法｜JANコードがないときの理由コードの選び方

楽天市場（RMS）にnormal-item.csvをアップロードしたら、「カタログIDもしくはカタログIDなしの理由が必須です」というエラーで弾かれた——。

先に結論です。対処は二択です。

  1. JANコードがある商品 → カタログID 列にJANコード（13桁等）を入れる
  2. JANコードがない商品 → カタログIDなしの理由 列に理由コード（1〜5の半角数字）を入れる

どちらか一方が入っていればこのエラーは解消します。ただし、理由コードの選び方には罠があり、特に「1：セット商品」を安易に選ぶと「セット商品用カタログIDは必須です」という二次エラーで再び止まります。

この記事では、理由コード1〜5の一覧と選び方、セット商品の罠の回避策、JANコードの調べ方、そしてこのエラーとセットで出やすい必須商品属性のエラーまで解説します。

なぜこのエラーが出るのか：SKUごとにカタログ情報が必須のジャンルがある

楽天では、ジャンルによってSKUごとにカタログIDの登録が必須になっています。カタログIDとは実質的にJANコードのことで、楽天が商品を製品カタログと照合するために使います。

該当ジャンルでは、CSVのSKU行に次のいずれかが入っていないとアップロードが通りません。

  • カタログID（JANコード等、文字列30桁以内）
  • カタログIDなしの理由（1〜5の半角数字）

両方空のままアップロードすると「カタログIDもしくはカタログIDなしの理由が必須です」になります。マルチSKU商品の場合はSKU行ごとに要求される点にも注意してください。1行だけ入力漏れがあっても弾かれます。

カタログIDなしの理由コード1〜5の一覧と選び方

カタログIDなしの理由 に入れられるコードは次の5つです。

コード 意味 使いどころ
1 セット商品 複数商品の詰め合わせ等。★二次エラーの罠あり（後述）
2 サービス商品 役務・チケット等、モノでない商品
3 当店オリジナル商品 自社企画商品でJANを取得していない場合
4 項目選択肢別在庫商品 旧・項目選択肢別在庫からの移行商品等
5 該当商品コードなし JANが存在しない・不明な場合の受け皿

選び方はシンプルで、JANが本当に存在しない理由を正直に選ぶのが基本です。自社企画品なら3、モノでないなら2、それ以外でJANがないなら5が受け皿になります。

罠：理由「1：セット商品」を選ぶと「セット商品用カタログIDは必須です」になる

一番ハマりやすいのがここです。カタログIDなしの理由 に 1（セット商品）を入れると、今度は セット商品用カタログID 列の入力が必須になり、「セット商品用カタログIDは必須です」という二次エラーが出ます。理由1は「カタログIDを免除するコード」ではなく、「セット専用のカタログIDを別途要求するコード」なのです。

回避策：実体が同じ商品なら本体と同じJANを入れる

実戦的な回避策は、「本体＋特典（おまけ）」のように実体が同一商品なら、特典付きSKUにも本体と同じJANを カタログID に入れることです。これで理由1のセット扱い自体を回避でき、二次エラーも発生しません。

たとえば「電子ピアノ本体」と「電子ピアノ＋お手入れクロス特典付き」の2SKUなら、どちらのSKUにも本体のJANを入れるのが簡単です。

本当に複数商品の詰め合わせで本体JANが使えない場合は、理由1＋セット商品用カタログID の入力が必要になります。運用が複雑になるため、自社企画のセットであれば「3：当店オリジナル商品」が使えないかも検討してください。判断に迷う場合は、RMSで最新のガイドラインを確認するのが確実です。

JANコードの調べ方

手元の商品のJANが分からない場合は、次の順で確認します。

  1. 商品パッケージのバーコード：バーコード下の13桁（または8桁）の数字がJANコードです
  2. メーカーの公式カタログ（PDF）や商品ページ：型番で検索すると記載されていることが多いです
  3. 大手小売サイトの商品ページ：型番で検索し、商品仕様欄のJAN表記を確認します

いずれの場合も、型番とカラーが完全に一致しているかを確認してから転記してください。同じ型番でもカラー違いでJANが異なるのが普通です。

あわせて出やすいエラー：必須の商品属性（ブランド名・メーカー型番・代表カラー）

カタログIDのエラーを直した後に、「必須の商品属性を指定してください」というエラーに進むケースがよくあります。ジャンルによっては、ブランド名・メーカー型番・代表カラー などの商品属性がSKU単位で必須だからです。

商品属性は「項目・値・単位」の3点セットのカラムで設定します。

商品属性（項目）1 = ブランド名      商品属性（値）1 = ヤマハ
商品属性（項目）2 = メーカー型番    商品属性（値）2 = YDP-166B
商品属性（項目）3 = 代表カラー      商品属性（値）3 = ブラック

注意点は2つです。ヘッダー名は 商品属性（項目）1 のようにカッコが先・番号が後（商品属性1（項目） は誤り）。そしてブランド名と代表カラーは楽天のマスター値と照合されるため、弾かれた場合はエラー文が指定する標準的な表記（代表カラーならブラック／ホワイト／ブラウン等）に合わせてください。

カタログIDの入力漏れを自動チェックできる無料ツール

マルチSKU商品が増えてくると、「どのSKU行でカタログIDと理由の両方が空になっているか」を目視で探すのは大変です。

無料のブラウザツール RakuCSV Studio の点検機能を使うと、手元のnormal-item.csvを読み込ませるだけで、カタログID（または理由コード）が欠落しているSKU行を自動で検出できます。あわせて、文字コード（UTF-8保存）やヘッダー名の誤記、環境依存文字といった別系統のエラー要因も同時に診断し、修正済みのCSVをダウンロードできます。ブラウザ上で動くのでインストールは不要です。

さらに詳しく：CSV登録を「一発で通す」ために

カタログIDを直しても、その先には「ジャンルIDが古い」「必須商品属性のマスター値照合」「スマホ用説明文のタグ制限」など、別系統のエラーが控えていることがあります。
